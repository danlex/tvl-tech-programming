# Facilitator Guide

Use this if you want to run the training live with managers in 35 to 60 minutes.

The simplest delivery format is browser-first: have everyone open `index.html` and edit code there.
The current version is mobile-first, so it also works well on phones.

If you want alternative delivery formats, use [CURRICULA.md](/Users/adan/work/claude/code/tvl-tech-programming/CURRICULA.md).

## Training objective

Help managers feel comfortable reading and discussing simple TypeScript, not mastering software engineering.

## Opening message

You can start with this:

"Programming is just a structured way to describe information, rules, and outcomes. If you already think about priorities, capacity, risk, or reporting, you already think in a way that is compatible with programming."

## Session flow

### Part 1: What code is

Time: 10 minutes

Explain:

- Code is a precise set of instructions
- Computers are literal
- TypeScript adds structure on top of JavaScript

Prompt:

- "Where in your job do you already apply rules to information?"

## Part 2: Lesson walkthroughs

Time: 20 to 30 minutes

Run each lesson in the browser page and pause after each one.

Encourage people to use both buttons:

- `Run code` to see behavior
- `Run tests` to check whether their change still satisfies the lesson or exercise

### Lesson 1

Focus:

- Variables store information
- Values can be changed and re-run quickly

Ask:

- "What business values could we store in variables?"

### Lesson 2

Focus:

- `if` statements turn decisions into code

Ask:

- "What is an example of an escalation rule from your world?"

### Lesson 3

Focus:

- Functions package reusable logic

Ask:

- "What repeated communication or reporting task could become a function?"

### Lesson 4

Focus:

- Arrays represent lists
- Simple counting and inspection

Ask:

- "What list do you track often in your work?"

### Lesson 5

Focus:

- Objects model real things
- Types make expectations explicit

Ask:

- "What fields would you track for a project or hiring plan?"

## Part 3: Exercises

Time: 10 to 15 minutes

Let participants try:

- the final challenge lesson in `index.html`

Encourage them to work in pairs and make small changes first.
When they think they are done, have them press `Run tests` before looking at the solution.

## Part 4: Debrief

Time: 10 minutes

Discussion questions:

- What felt easier than expected?
- What felt unfamiliar?
- What part looked most useful for talking with engineering teams?

## Key messages to reinforce

- Reading code is easier than writing code
- Most business logic is simpler than it looks
- Types are helpful because they reduce ambiguity
- Managers do not need to become engineers to benefit from understanding code
